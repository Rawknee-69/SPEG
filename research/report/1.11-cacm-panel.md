## CacmPanel behavior

- **On mount**: `CacmClient.connect()` → `sessions({project})` + `query({project, limit: 100})` (query skipped when no project is open — the daemon's `cacm.query` requires `project`). Loading / ready / error states with a **Retry** button when the daemon is unreachable.
- **Timeline rows**: color dot + agent label per `AgentType` (`AGENT_META`, distinct hues), a task summary (newest extracted context's content, truncated; falls back to the session path tail), relative timestamp, expand chevron.
- **Expand**: shows the session's extracted contexts — type badge (Task/Decision/File change/Error/Pattern), content, folded **Decision**/**Error** notes, and touched file paths.
- **Inject context**: calls `cacm.inject({sessionId, agent})` and hands the formatted reminder to `onInjectContext`; ChatView inserts it into the composer draft via `composerRef.insertTextAtEnd(formatted, { ensureLeadingBoundary: true })`. Buttons show "Injecting…" and disable while a request is in flight; failures surface inline.
- **Auto-refresh**: subscribes to daemon-pushed `cacm.session_activity` notifications and reloads the timeline on each event; `client.close()` in the effect cleanup stops the socket (SDK reconnects on next use).

## Decisions (deviations from the letter of the task, all reversible)

- **Test lives in `apps/web/src/components/speg/`**, not `apps/web/test/`: the web unit project's include glob is `src/**/*.test.{ts,tsx}` (`apps/web/vite.config.ts`), so a test under `apps/web/test/` would never run under `vp test run --project unit` — it would only typecheck. Co-location matches the ~200 existing web tests.
- **`RightPanelTabs.tsx` and `ChatView.tsx` were touched** even though the task's file list only names `CacmPanel.tsx` + `rightPanelStore.ts`: the tab cannot appear or render without them ("follow the existing pattern" per the RESEARCH section). Changes are minimal and mirror the existing plan/diff/files plumbing.
- **`@cacm/sdk` registered in the pnpm workspace** (`cacm/cacm-sdk-ts` added to `pnpm-workspace.yaml`, `workspace:*` dep in apps/web) instead of a `file:`/published dep — consistent with every other internal package. A `prepare: tsc` script builds `dist/` (git-ignored) on `pnpm install` so fresh clones work.
- **Injection target is the composer draft** (via the existing `ChatComposerHandle.insertTextAtEnd`), the same place terminal context lands; the panel stays decoupled by only exposing an `onInjectContext` callback.
- **Single load effect** for connect+load+activity-subscribe+close (StrictMode-safe: `close()` then `connect()` restarts the SDK client per its documented semantics).

## Notes / Follow-ups

- **Empty-query UX**: with no project open, `cacm.query` can't run (project is required server-side), so expanded sessions show "No extracted context for this session yet." The session list still shows all agents. A daemon-side "contexts for a session id" endpoint would let the panel show per-session context without a project.
- **Activity-driven reload is unthrottled** (one reload per pushed event); if watchers fire frequently this could be debounced — cheap to add when needed.
- **Live e2e in `vp run dev`** (task's integration step) is the natural Phase-1 gate check once the daemon ships as a service; here it was approximated by the real-daemon SDK smoke above.
- `research/promptref.md` working-tree modifications predate this task and were left untouched.
