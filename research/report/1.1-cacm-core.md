## Key Decisions

- **Workspace members include stub crates** — the spec lists `["cacm-core", "cacm-daemon", "cacm-sdk-rs"]`; cargo refuses to resolve missing members, so `cacm-daemon`/`cacm-sdk-rs` are placeholder lib crates (task 1.4/1.8 will replace them).
- **`AgentType` wire names use explicit `#[serde(rename)]`**, not `rename_all = "kebab-case"`: kebab-casing `OpenCode` would produce `open-code`, but the task 1.2 contract says `opencode`. Explicit renames keep all six names exactly matching the TS contracts.
- **`agent_type(&self)` instead of an associated `agent_type()`** — a no-self method can't be called through `Box<dyn AgentSessionParser>`, and the registry keys parsers by their own agent type, so the trait method takes `&self` (documented in code).
- **Watcher session-id heuristic is extension-based, not event-kind-based** — Windows `notify` may deliver a create as `Create(Any)` or a metadata modify before the write; deriving "is a file" from the path extension instead keeps the heuristic stable across platforms. Precise per-agent extraction is left to the parsers (1.5+).
- **Deviation: report filename** — task text says `research/report/1.1-cacm-core.md`; followed literally (existing reports `1.1-scaffolding.md`, `1.2-contracts.md` suggest the number was meant to be `1.3`, but no instruction to rename was given).

## Toolchain Note (important for this machine)

This machine has the **MSVC toolchain but no Windows 10 SDK** (`kernel32.lib`/`ucrt.lib` absent, no `KitsRoot10` registry key) and runs **non-admin**, so MSVC linking is impossible (`cargo` fails linking build scripts with `LNK1181: cannot open input file 'kernel32.lib'`). Per user decision, the cacm workspace now builds with the **GNU toolchain**:

- `rustup override set stable-x86_64-pc-windows-gnu` in `cacm/` (persisted in `rustup` settings)
- WinLibs mingw-w64 (POSIX threads, UCRT) installed via winget; linker path pinned in **gitignored** `cacm/.cargo/config.toml` (`[target.x86_64-pc-windows-gnu] linker = ...`)
- `dlltool`/`as`/`ar`/`ranlib`/`ld` + their DLLs copied to `~/.cargo/bin` (this session's PATH predates the winget install; `dlltool` is required by rustc for system import-lib generation on GNU targets)

This is machine-local configuration only — nothing environment-specific is committed to git.
