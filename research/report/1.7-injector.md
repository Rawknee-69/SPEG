# Task 1.7: Context Injector (query + rank + format)

**Agent**: Reasonix | **Status**: ✅ | **Time**: ~45min

## What Was Done

Implemented the context injector in `cacm/cacm-core/src/injector.rs` — the read-side counterpart of the extractor. [`ContextInjector`] runs the full pipeline **query → rank → format** and returns a `String` ready to be prepended/appended to a target agent's prompt. No new dependencies (chrono/serde already present; `f64::exp` is std).

Public surface:

- **`ContextInjector<S: ContextSource>`** — `new(source)`, builders `with_fixed_now` / `with_limit` / `with_top_n` / `with_max_chars`, and the three spec methods:
  - `inject(project, target_agent, session_id: Option<&str>) -> String`
  - `query_context(project, limit) -> Vec<CrossAgentContext>`
  - `rank_context(entries, target_agent, session_id) -> Vec<RankedContext>`
  - `format_context(entries, target) -> String`
- **`ContextSource` trait** — minimal query abstraction so `cacm-core` (which cannot depend on `cacm-daemon`) stays decoupled; a blanket impl makes any `Fn(&str, usize) -> Vec<CrossAgentContext>` a source, so the daemon wires its `Storage::query_context` with a one-line closure.
- **`RankedContext`** — entry + `recency_score` / `relevance` / `confidence` / `final_score`.
- **Pure scoring functions** (free, `pub`, deterministic): `recency_score`, `relevance_score`, `confidence_score`, `final_score`, `time_ago`, `context_type_label`.

## Ranking (spec formula, spec weights)

```text
recency_score = e^(-hours_ago / 24.0)        // τ = 24 h exponential decay
final_score   = recency × 0.5 + relevance × 0.3 + confidence × 0.2
```

- **Recency** is the mean-lifetime form of exponential decay (`N(t) = N₀e^(−t/τ)`): 0 h → 1.0, 24 h → `e⁻¹ ≈ 0.368`, 48 h → `e⁻² ≈ 0.135`. Future timestamps clamp to 1.0. (Research: canonical exponential-decay formula, Wikipedia; also used for BGP route-flap damping.)
- **Relevance** (heuristic, 0..=1, additive + clamp): `+0.4` entry belongs to the caller's `session_id`, `+0.3` entry's agent matches the target agent, `+0.2` Decision/Pattern (reusable), `+0.1` Task.
- **Confidence** (heuristic, 0..=1, additive + clamp): base `0.2`, `+0.3` Decision/Pattern, `+0.3` carries structured `decisions`/`errors`, `+0.2` names `file_paths`.
- Entries sort by `final_score` descending (ties → newest first), truncated to `top_n` (default 5; query pulls `limit` = 10).

These are deterministic stand-ins until embedding-based relevance lands; the component weights are documented constants (`RECENCY_WEIGHT` etc.) so they are tunable.

## Formatting per agent

| Target | Header | Line shape | Intended placement |
|---|---|---|---|
| Speg / Jcode | `[Cross-Agent Context]` | `• Task: … (agent, 5m ago)` | system reminder (spec-exact) |
| Claude Code | `## Cross-Agent Context` | `- **Task**: … (agent, 5m ago)` | append to `CLAUDE.md` |
| Codex | `[Cross-Agent Context]` | `• Task: … (agent, 5m ago)` | prepend to first user message |
| OpenCode | `## Cross-Agent Context` | `- **Task**: … (agent, 5m ago)` | append to `OPENCODE.md` |
| Cursor | `# Cross-Agent Context` | `- Task: … (agent, 5m ago)` | append to `.cursorrules` |

The `(agent, time_ago)` suffix uses the source agent's kebab-case name + a humanized age (`5m ago`, `2h ago`, `3d ago`). The Jcode/SPEG shape mirrors Jcode's `# System Reminder` dynamic-prompt pattern (`jcode/crates/jcode-app-core/src/agent/prompting.rs` — markdown header appended to the dynamic part of the split system prompt). "Prepend/append" is documented intent; `format_context` returns the bare block and the caller places it.

**Budget**: default `max_chars` = 2000 (spec). Lower-ranked entries are dropped whole when they would overflow; the top-ranked entry is *always* kept — if it alone exceeds the budget, its content is truncated at a UTF-8 char boundary with a `…` suffix (header always preserved). Empty store / no matching project → `""` (nothing to inject).

## Key Decisions

- **`rank_context` takes `(entries, target_agent, session_id)` rather than the spec's elided `rank_context(entries)`.** The spec signature is written as `Vec` with no generic — relevance cannot be computed without knowing *who* the context is for. These two signals (target agent, current session) are the only cross-agent ones stored entries carry, so they are passed explicitly and documented.
- **`ContextSource` trait instead of depending on the daemon.** `cacm-core` is the base crate; the daemon's `Storage::query_context` returns `Result`. The blanket `Fn` impl makes wiring a one-liner (`ContextInjector::new(|p, l| storage.query_context(p, l).unwrap_or_default())`), and tests use an in-memory `FakeSource` that mirrors the daemon `MemoryGraph`'s filtering (session_id / file_paths match, `*` = all, newest first).
- **Deterministic tests via a pinned clock.** `with_fixed_now` sets the scoring/`time_ago` clock; production uses `Utc::now()` at call time.
- **Empty context → `""`**, not a "no context" placeholder: for append-targets (`CLAUDE.md`, `.cursorrules`) injecting a header with nothing under it would be noise, and for prepend-targets nothing should be prepended. (The daemon's task-1.4 `format_inject` keeps its own placeholder; it can be rewired to the injector in task 1.8.)
- **Truncation is entry-granular** (drop lowest-ranked, never split an entry) except for the single top entry, which is content-truncated as a last resort — keeps each surviving bullet readable.
