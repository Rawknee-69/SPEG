## What Was Done

`cacm/cacm-sdk-ts/src/types.ts` — the TypeScript types for the CACM daemon's
WebSocket JSON protocol. The file already existed from task 1.9 (the `@cacm/sdk`
client shipped with its wire types); this task brought it into exact compliance
with the 1.14 spec and verified it end-to-end.

All types are **plain TypeScript** (union types + interfaces) — no Effect/Schema —
mirroring `cacm-core/src/types.rs` exactly, per the "simple JSON WebSocket
protocol, NOT Effect RPC" split from the v4 Effect/Schema contracts (task 1.2):

## Rename (this task's delta)

The task spec names the RPC types `CacmSessionsParams/Result` and the push type
`CacmSessionActivity`. Task 1.9 had shipped them as `CacmSessionParams/Result`
(singular) and `SessionActivity`. Per user decision, the SDK was renamed to the
exact 1.14 names across all four files:

- `src/types.ts` — declarations + doc comments; also fixed a stale header-comment
  task reference (`task 1.13` → `task 1.14`).
- `src/client.ts` — imports, `sessions()` signature, `onActivity()` listener
  type, and the `record.data as CacmSessionActivity` cast.
- `src/index.ts` — re-exports (`CacmSessionActivity` inserted alphabetically
  before `CacmSessionsParams/Result`; `SessionActivity` removed from the tail).
- `test/client.test.ts` — import + `sampleActivity`/`seen` annotations.

`SessionEventType` was kept as-is: it is the companion enum for the activity's
`event_type` field and is not in the task's name list. No other consumers were
affected — `CacmPanel.tsx` (apps/web) imports only `CacmClient`, `AgentSession`,
`AgentType`, `ContextType`, `CrossAgentContext` from `@cacm/sdk`.

**Wire format is unchanged**: these are TS type names only; JSON field names
(`session_id`, `event`, `data`, …) and the RPC method names (`cacm.sessions`,
`cacm.session_activity`) are untouched, so the daemon and sdk-rs need no changes.
