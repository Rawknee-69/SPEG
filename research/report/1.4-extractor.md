## What Was Done

Implemented the heuristic context extractor in `cacm/cacm-core/src/extractor.rs` — pure, testable functions over `&[AgentTurn]` plus a session-scoped `ContextExtractor` that composes them into `CrossAgentContext` entries and batches extraction. No LLM dependency (MVP); the LLM upgrade path is documented and the swap-in point is `ContextExtractor::extract_context`.

Heuristic functions (all free functions, `pub`, deterministic):

- **`extract_task(turns)`** — the first non-empty user message = task description (spec's headline rule). `looks_like_task(text)` gates emission on the spec keywords (`"I want to"`, `build`, `create`, `fix`, `implement`, `refactor`), case-insensitive substring match.
- **`extract_decisions(turns)`** — user/assistant messages containing decision keywords (`decided`, `chose`, `going with`, `will use`, `using`), deduplicated, in turn order.
- **`extract_file_changes(turns)`** — file paths from three sources, most authoritative first: structured `FileModification` records (incl. Delete/Rename), path-shaped tool-call JSON inputs (`path`/`file_path`/`file`/`old_path`/`new_path`/`source`/`destination` — rename records both old and new), and message text (`Modified:`/`Created:`/`Wrote to:`-style prefixes plus file-extension tokens against a known-extension allowlist). Paths are de-quoted/de-punctuated, deduplicated, and boundary-guarded so decimals (`3.14`), URLs (`example.com`), version strings (`v1.2.3`), and bare words (`Deleted: all the old files`) are rejected.
- **`extract_errors(turns)`** — messages with `error`, `failed`, `broke`, `exception`, `cannot`.
- **`extract_patterns(turns)`** — messages with `always`, `never`, `convention`, `best practice`, `pattern`.

`ContextExtractor` (session-scoped): `new(session_id, agent_type)`, `with_batch_size(n)` (default **5**), `add_turn(turn)` (flushes when the buffer reaches the batch size), `flush()` (session end — extracts the remainder), and `extract_context(&[AgentTurn])` (one-shot over any batch). Per batch it emits up to one `CrossAgentContext` per type (Task / Decision / FileChange / Error / Pattern, deterministic order), stamps `session_id`/`agent_type`, timestamps entries with the batch's last turn, fills `file_paths`/`decisions`/`errors` fields (which the daemon's project-matching queries read), truncates items to `MAX_ITEM_CHARS` (512), and generates unique ids (`<session_id>-<seq>`). The Task is judged from the **session's first** user message exactly once (`task_decided` closes the gate even when the keyword check fails), so a later batch's message is never mislabeled as the task.

## Key Decisions

- **Pure functions + one composing struct.** Each heuristic is a free, testable function; `ContextExtractor` holds only session metadata, the turn buffer, the id sequence, and the once-per-session task gate. This keeps the "pure functions — receive AgentTurn, return extracted context" spec property while giving the daemon a stateful batched surface.
- **`extract_task` returns the first user message; keyword gating lives in `extract_context`.** The spec's headline rule and its keyword list are both honored: the pure function implements the rule, and `looks_like_task` decides whether the message is worth emitting. A keyword-less first message means no Task entry — a documented MVP heuristic limitation.
- **Task judged once, from the session's first user message.** `task_decided` is set the first time any batch contains a user message, *before* the keyword gate — a later batch can never become "the task". (Review follow-up: the first version left the gate open on keyword failure, which would have mislabeled a later batch's message.)
- **Text path extraction is deliberately conservative** (regex has no look-around, so boundaries are enforced in code): known-extension allowlist + separator/extension path-like check. This rejects `3.14`/`example.com`/`v1.2.3` and bare words, at the cost of missing extensionless prose mentions (`Created: Makefile`) and case-mismatched extensions (`README.MD`) — the structured `file_modifications` and tool-input sources carry those reliably. Documented in the module's "Known heuristic limits".
- **Batching matches the spec**: extraction every 5 accumulated turns (`DEFAULT_BATCH_SIZE`) or at session end (`flush`). A single turn still extracts when the session ends. Full batches and the remainder produce separate `CrossAgentContext` entries with unique ids; the Task appears exactly once across the whole session.
- **`extract_context` takes `&[AgentTurn]`** rather than `Vec<AgentTurn>` (avoids cloning the caller's buffer); the spec signature is preserved in spirit.
