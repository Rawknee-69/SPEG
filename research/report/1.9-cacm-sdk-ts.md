## CacmClient API

```ts
const client = new CacmClient();                       // ws://localhost:9786 → /ws
await client.connect();
const { entries }  = await client.query({ project: "/repo", limit: 10 });
const { sessions } = await client.sessions({ project: "/repo" });
const { formatted } = await client.inject({ sessionId: "ses_abc", agent: "jcode" });
const unsubscribe = client.onActivity((activity) => …); // cacm.session_activity push
client.close();
```

- **Wire protocol** (matches `cacm-daemon/src/server.rs` + `handlers.rs`): `cacm.ping` → `"pong"`, `cacm.query` → `{entries}`, `cacm.sessions` → `{sessions}`, `cacm.inject` → `{formatted}`, pushes `{"event":"cacm.session_activity","data":{…}}`. No changes to the daemon were needed.
- **Types** (`src/types.ts`) mirror `cacm-core/src/types.rs` exactly: `AgentType` (kebab-case), `SessionStatus`, `AgentSession`, `AgentTurn`/`ToolCall`/`FileModification`/`FileChangeKind`, `ContextType`, `CrossAgentContext`, `SessionActivity`/`SessionEventType`, plus `CacmQueryParams/Result`, `CacmSessionParams/Result`, `CacmInjectParams/Result` (task 1.13's "types.ts must mirror types.rs exactly").
- **Connection**: one persistent native `WebSocket` (browser + Node ≥ 22.18); `connect()` awaits the `open` event; URL normalization accepts `host:port`, `ws://host:port`, and appends the daemon's `/ws` route.
- **Request/reply correlation**: monotonic `id`, `pending` `Map` with per-request timeout (30 s), replies matched by id while server notifications (`{"event": …}`) are dispatched to `onActivity` listeners and skipped by correlation; unknown ids ignored.
- **Auto-reconnect with exponential backoff**: on drop, pending requests fail fast with `kind: "transport"` and the client reconnects in the background at 100 ms → 10 s (×2), up to 8 attempts; a later request transparently uses the fresh connection. `connect()` failures reject with `kind: "connect"` (also on a connect timeout, 10 s) and never hang.
- **Errors**: `CacmError { kind: invalid-address | connect | transport | timeout | rpc | protocol, code? }` — mirrors `CacmError` in `cacm-sdk-rs`.
- **Zero runtime dependencies**: platform `WebSocket` only; `typescript` + `@types/node` are dev-only.

## Tests (19/19 green)

`npm test` builds first, then runs `node --test` against the mock-WebSocket suite (mocking the daemon via `globalThis.WebSocket`, matching the task's "Mock WebSocket for unit tests"):

- URL normalization (`/ws` appending, bare `host:port`, `wss://`, query strings, invalid input).
- `connect()`: resolves on open, already-open short-circuit, rejection on refusal, **connect timeout** when a socket never opens, invalid-address rejection.
- `query`/`sessions`/`inject`/`ping` roundtrips (params asserted, replies parsed).
- Concurrent request correlation by id.
- RPC error propagation (`kind: "rpc"`, code, no retry), request timeout, malformed-reply protocol errors.
- `onActivity` notification delivery + unsubscribe; notifications don't disturb pending correlation.
- **Reconnect behavior**: drop → in-flight request rejects with `transport` → background reconnect after the backoff delay (delay asserted) → next request succeeds on the new socket; give-up after `maxReconnectAttempts`; `close()` rejects in-flight requests and stops reconnection.

## Design decisions (deviations from the letter of the task, all reversible)

- **`query`/`sessions`/`inject` return the full result envelope** (`{entries}`, `{sessions}`, `{formatted}`) since the task names `CacmQueryResult`/`CacmSessionResult`/`CacmInjectResult` as types to define; the sdk-rs equivalent returns bare arrays/strings.
- **`onActivity` returns an unsubscribe function** (superset of the task's `void` signature — callers may ignore it).
- **Extra `ping()` and `sessions({project?})` default params** — mirrors the sdk-rs surface.
- **`constructor(url = "ws://localhost:9786", options?)`** — the task's default URL has no path; normalization appends the daemon's real `/ws` route so the default actually works. Tuning knobs (`timeoutMs`, `connectTimeoutMs`, `backoffBaseMs`, `backoffMaxMs`, `maxReconnectAttempts`) make tests fast and deterministic.
- **`close()` is a stop; a later `connect()` restarts** (documented). Flagged by the built-in review as a possible surprise; kept intentionally — it matches "close stops, connect restarts" and no automatic reconnect happens after `close()`.
- **Tests import the built `dist`** (jcode-sdk pattern): source uses `.js` specifiers so the published `.d.ts` is consumer-safe (`.ts` specifiers in emitted `.d.ts` would break consumers — discovered during verification and fixed).

## Post-review hardening

Built-in review (sa_20260805_104920) verified correlation/timer/pending cleanup, notification dispatch, and bounded backoff as correct; two findings fixed before shipping:

1. **Stale-socket close guard** — `handleClose` now takes the closing socket and ignores it when a reconnect already took over (`this.ws !== closed`), so a duplicate/superseded close can't null a live connection or fail new pending requests.
2. **Connect timeout** — a socket that never reaches `OPEN` now rejects the attempt with `kind: "connect"` (10 s default, `connectTimeoutMs` option) instead of hanging `connect()` forever; regression test added.
