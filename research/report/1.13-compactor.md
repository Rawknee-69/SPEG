# Task 1.13: Cross-Session Context Compactor

**Agent**: Reasonix | **Status**: ✅ | **Time**: ~1.5h

## What Was Done

Implemented the compactor in `cacm/cacm-core/src/compactor.rs` — the cross-session
consolidation stage that runs during the daemon's ambient cycles (or on demand) to
keep the stored `CrossAgentContext` population deduplicated, summarized, linked, and
free of stale noise. Pure, deterministic, and daemon-independent: it takes
`&[CrossAgentContext]` and a pinned `now` clock, so it needs no new dependencies
(chrono/serde/regex already present) and the daemon wires it with a one-liner.

Public surface (all free `pub` functions + a composing struct, matching the
extractor/injector style):

- **`deduplicate(entries)`** — group by `file_path`, keep the highest-confidence
  representative per group (confidence = the injector's `confidence_score`, so the
  compactor and the ranker agree on what "good" means). File-less entries are
  deduplicated only on exact content equality. Output preserves input order.
- **`summarize_to_milestones(entries)`** — collapse each `(agent_type, session_id)`
  into one deterministic _milestone_ entry: template summary (`[Milestone] N entries
… Task: … Decisions: … Files: … Errors: …`), with `file_paths` / `decisions` /
  `errors` unioned in first-seen order and the group's newest timestamp. The content
  template is the documented LLM upgrade point (mirrors the extractor's swap-in path).
- **`link_related(entries)`** — cross-agent `related_to` edges
  (`ContextLink { from_id, to_id, weight }`, mirroring Jcode's `MemoryGraph`
  `EdgeKind::RelatesTo { weight }`): pairs of entries from _different_ agents scored
  `0.6 × file-Jaccard + 0.4 × content-token-Jaccard`, emitted once with
  `from_id < to_id` when `weight ≥ 0.15`.
- **`decayed_confidence(ctx, now, half_life)`** — exponential decay
  `confidence × 0.5^(age/half_life)` (30-day default half-life).
- **`prune_stale(entries, now, max_age, half_life, min_confidence)`** — returns
  `(kept, pruned)`: prunes entries older than `max_age` (365-day default) or whose
  decayed confidence fell below `min_confidence` (0.05 default).
- **`Compactor`** — builder (`new(now)` + `with_half_life` / `with_max_age` /
  `with_min_confidence` / `with_dedup` / `with_summarize` / `with_link` / `with_prune`)
  composing the pipeline **prune → dedup → link → summarize** into
  `compact(&[CrossAgentContext]) -> CompactionReport { milestones, links,
deduplicated, pruned, input_count }`.

## Key Decisions

- **No type changes to `CrossAgentContext`.** Dedup ranks with the injector's
  existing `confidence_score` (pub since task 1.7) instead of adding a
  `confidence` field, and links are a new `ContextLink` type living in
  `compactor.rs` rather than a `related_to` field — the wire protocol stays
  exactly as task 1.14 will mirror it, and the compactor remains a drop-in stage.
- **Milestone = one per `(agent_type, session_id)`**, not per agent: the spec's
  "multi-turn session → milestone" is session-scoped; the verification's 3 agents
  each had one session, so 10 → 3 holds either way.
- **Cross-agent dedup is by file path, literally per the spec** ("group by
  file_path, keep highest-confidence"), so an agent's duplicate of another
  agent's file entry collapses into that file group's representative. The
  tradeoff (an entry with distinct content on a shared file is dropped) is
  documented in the module; milestone summarization then distills each session's
  surviving representatives.
- **Links are content-similarity based** (semantic `RelatesTo`, like Jcode's
  memory graph): after cross-agent dedup, entries sharing a file across agents
  have already collapsed, so shared-file pairs can't also be link pairs —
  links express "related but distinct" across agents.
- **Staleness = max-age cap OR decayed-confidence floor**, both with defaults,
  so pruning is bounded but not pathologically aggressive (a plain Task needs
  ~2 half-lives / 60 days to fall under the 0.05 floor).
- **Deterministic everywhere**: pinned `now`, confidence-then-timestamp-then-id
  sort keys, BTreeMap group ordering, `from_id < to_id` link canonicalization,
  input-order-preserving dedup. The daemon can run this in its ambient loop
  without flapping results.
