## Key Decisions

- **axum over warp** — axum is the current standard (warp's maintenance is quieter), the WS upgrade + tower ecosystem is a good fit, and the spec's own commit message prescribes axum. axum 0.8 requires the `ws` feature and `Message::Text(Utf8Bytes)`.
- **Full harness-protocol client deferred to task 1.8** — per the checklist, the `jcode-cacm-bridge` (task 1.8) wires the real NDJSON write path into Jcode's memory graph. Task 1.4's `JcodeBackend` keeps context in an in-memory graph (mirroring Jcode's `MemoryGraph`) and honestly probes the harness socket for availability; the auto-select falls back to SQLite when no daemon is reachable (the path exercised on this machine).
- **rusqlite `bundled`** — no system SQLite dependency; compiles the amalgamation with the mingw gcc (WinLibs bin dir must be on `PATH` for the cc build script — machine-local, not committed).
- **`cacm.context.store` extension** — additive, spec surface untouched; gives `store_context` a wire path and 1.6 a home.
- **Session index lives in `AppState`** (fast, watcher-updated); `Storage::list_sessions` hydrates it at startup from the SQLite table, so sessions persist across restarts (verified).
- **`&**storage`instead of`&\*storage`** — with `Arc<Mutex<Box<dyn Storage>>>`, the trait-object coercion through the box needs the explicit double-deref; boxed trait object also sidesteps the `Mutex<dyn Storage>` unsizing problem.
- **Close handshake** — tungstenite queues the close-ack during `read()`; `SinkExt::close` flushes it. The `1006` seen in one test was an undici race (closing synchronously inside `onmessage`) that reproduces identically against the public `echo.websocket.events` server — not a daemon bug (clean `1000/wasClean=true` with a small delay).

## Post-review fixes (same task, commit `06ede0e0`)

Review of the committed daemon (built-in review) flagged should-fix items, all addressed in a follow-up commit:

- **Per-connection request/reply correlation** — the pending map is keyed `<conn_id>:<id>` (monotonic `AtomicU64` per connection) so two clients reusing `"id": 1` no longer collide; `dispatch` takes `conn_id`; cross-client collision test added.
- **Separator-aware project matching** — `path_within` (with root/trailing-separator handling) so `/repo` no longer matches `/repo2`; ordering normalized to timestamp-desc in both backends.
- **Security posture** — daemon now binds **loopback by default** (`--host` to override) and rejects WebSocket upgrades whose `Origin` is not on an explicit `--allow-origin` allow-list (403); CORS restricted to the allow-list when configured. Non-browser clients (no Origin) keep working.
- **watcher_task** — upserts the session index instead of first-seen-only, and a poisoned index/storage lock no longer swallows the storage write or the client notification (both log a warning); integration test added.

Tests grew from 31 → 35 (33 lib + 2 bin).

## Security review (commit `4b3e0977`)

Security review verdict: **no blockers — posture sound** (loopback bind + exact-match Origin allow-list; no SQL injection — fixed parameterized queries; no lock-poisoning panic paths in prod; per-connection pending map with no unbounded growth). Its should-fix items were implemented:

- **Non-loopback bind refused** unless `--expose` is passed (unauthenticated data otherwise).
- **WS frame size capped at 1 MiB** and **concurrent connections capped at 64** (connection-slot acquire/release with test).
- **In-memory graph dedup + cap** — same-id stores replace (matching SQLite `INSERT OR REPLACE`), oldest evicted beyond 10 000 entries; dedup verified live.
- **SQLite DB file 0600** on Unix (context transcripts are sensitive).
- **Server-error masking** — `-32000` details (paths/backend internals) are logged and replaced with a generic message to the client (covered by a failing-storage test).

Tests grew 35 → 39 (36 lib + 3 bin).

A follow-up hardening commit (`277f5b8f`) addressed the low-severity items from the re-review: **RAII `ConnectionGuard`** (connection slot released on drop — panic-safe), **atomic 0600 DB-file creation** (no open-then-chmod window), and a **64 MiB byte budget** in addition to the 10 000-entry cap. Commit `866bdc15` made the byte budget count **all string fields** (file paths, decisions, errors — not just content). Commit `d069f3d8` addressed the final review's should-fixes: **bulk graph eviction** (one O(n log n) sort+truncate pass instead of O(n²) under the storage mutex), **real-socket handshake tests** (tokio-tungstenite dev-dep: origin 403, connection-cap 503, end-to-end ping), **typed request parsing** (dispatch deserializes `RpcRequest`), separator-aware session filtering, and broader loopback detection. Tests now 44 (41 lib + 3 bin).
